# CITY OS v4.0 多灾种世界模型

> 状态：区级/流域级可审计筛查模型。所有脆弱性、堤顶和水力参数均为待权威数据替换的先验，不能替代业务水动力、地质灾害或结构风工程模型。

## 1. 统一结构

台风轨迹是共同强迫源，派生空间降雨、风、气压和风暴增水：

```text
track(t) -> {rain(x,t), wind(x,t), pressure(t), surge(t)}
             |             |                    |
             v             v                    v
      城市/河流/地质     风致损伤          海岸复合洪涝
```

各域保留独立、有单位的状态和审计，不把概率状态伪装成质量守恒量：

- 城市地表水：`surface_storage_m3`；
- 海水入侵：`marine_storage_m3`；
- 河流：`channel_flow_m3_s + floodplain_storage_m3`；
- 地质：`soil_saturation + trigger_probability`；
- 风致损伤：树木与幕墙的脆弱性概率状态。

## 2. 海岸洪涝

`backend/app/coastal.py` 接受带站点、基准面、来源和可用时刻的真实/预报水位边界。缺测不以零填充。海水越过岸段高程时按宽顶堰先验计算入流，并在低潮期显式回排：

```text
Vmarine[t+1] = Vmarine[t] + marine_inflow - marine_return
Vtotal = Vsurface + Vmarine
```

雨洪、海水和同化增量必须分账。默认堤顶高程和有效宽度仅用于模型演示，正式使用前必须换成测绘岸线、堤防和排口数据。

## 3. 山洪与中小河流

`backend/app/river.py` 使用有向河网节点，强迫为流域面雨和上游来水边界，状态为河道流量及沿河滞蓄体积。河道超出过流能力后进入洪泛区，退水再回到河道。河道流量观测使用确定性 EnSRF 更新，并把同化增量单独记账。

默认河网仅是深圳主要流域的可运行先验，不是权威河道断面数据库。

## 4. 内涝—地质耦合

`backend/app/geohazard.py` 增加土壤饱和记忆。动态产流系数由不透水率、土壤饱和及坡度共同决定；滑坡/泥石流触发强度由坡度、地质脆弱性、植被、当前雨强和 24 小时前期雨量决定。

`trigger_probability` 是未校准的累计模型信念，不是历史频率，也不进入水量平衡。

## 5. API

- `POST /api/hazards/coastal`：真实水位边界 + 分区降雨；
- `POST /api/hazards/river`：流域面雨 + 上游流量；
- `POST /api/hazards/geology`：雨量 + 坡度/土壤/地质/地表覆盖；
- `POST /api/hazards/typhoon`：逐小时台风轨迹统一驱动全部灾种。

所有请求体拒绝未知字段、非有限数值和越界物理量。

## 6. 数据合同

动态数据至少保存：

- `valid_at`：物理有效时间；
- `available_at`：进入系统时间；
- `source` 与 `quality_flag`；
- 潮位的 `datum`；
- 台风资料的签发时刻和原始轨迹版本；
- 河流观测的站点、断面和流量单位；
- 地质事件的事件时间、位置、类型和独立标注来源。

回放只能使用 `available_at <= forecast_issued_at` 的资料。不同潮位基准面在没有可追溯换算前禁止合并。

## 7. 验证顺序

1. 数值守恒、非负、强迫单调性和输入边界测试；
2. 天鸽、山竹、苏拉与 2023-09-07 暴雨的冻结回放；
3. 以“高潮弱雨、强雨低潮、强增水弱雨”为负样本；
4. 河流按独立流域事件验证峰值流量、峰现时间和洪泛深度；
5. 地质灾害按事件级空间外推验证，并校准概率可靠性；
6. 多灾种整体只在各子域分别通过验证后评估。
