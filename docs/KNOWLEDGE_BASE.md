# 沉淀知识库 — 架构与数据说明

> 版本：kb-2026-08-28-v1 ｜ 参照 cityos-command-workbench「沉淀知识库」设计，内容全部来自本项目真实数据层。

## 一、总体架构

```
前端 KnowledgeBasePanel.jsx（四 Tab）
  ├─ 📚 案例沉淀    6 个真实事件档案 + 模型回放日序列
  ├─ 🤖 城安助手    RAG 问答（三段式检索 + 大模型生成）
  ├─ 🏙️ 城市底座    人口/建筑/地形/隐患点暴露统计
  └─ 🧪 模型档案    三个监督模型指标 + 诚实局限
        │
        ▼ /api/knowledge/*
后端 app/knowledge.py
  ├─ CASES          6 事件案例（真实观测 + ML 回放）
  ├─ CITY_BASE      城市底座统计（栅格真实计算）
  ├─ MODEL_ARCHIVE  模型档案
  └─ ask()          城安助手 RAG 问答
```

## 二、城安助手 · 三段式 RAG 检索

```
用户问题
  │
  ├─① 语义召回  Qwen3-Embedding-8B（aiping.cn）
  │     全量 6 案例 → 检索文本 embedding → 余弦相似度 → top 2k 候选
  │
  ├─② 精排      bge-reranker-v2-m3（aiping.cn）
  │     候选案例全文 → rerank 打分 → top-3（阈值 0.05）
  │
  ├─③ 生成      deepseek-v4-flash-vision-exp（自建 OpenAI 兼容服务）
  │     系统 prompt（回答纪律 + 输出格式）+ 案例上下文 → 结构化回答
  │
  └─ 回退链     rerank 失败 → 语义相似度（阈值 0.45）
                embedding 失败 → BM25 关键词（本地，零依赖）
                LLM 失败 → 本地规则回答（字段拼接）
```

### 设计要点

1. **引用与待确认由本地结构化生成**：无论 LLM 是否可用，`citations`（回答依据）与 `needs_confirm`（还需确认）都来自案例的结构化字段，保证真实可溯、不被 LLM 幻觉污染。
2. **LLM 只做自然语言组织**：系统 prompt 明确纪律——只能依据条目回答、概率是历史回放非实时预报、缺口如实列出不推测补全。
3. **逐级回退**：三个外部服务任一失败都有本地兜底，服务永不可用。
4. **进程内向量缓存**：案例库静态，embedding 只在首次计算后缓存（`_EMBED_CACHE`）。

## 九、风暴潮子系统（2026-08-28 新增）

`backend/app/surge.py` — 自包含风暴潮模块（零外部实时依赖）：

### ① 天文潮谐波推算
- 数据源：HKO 3 年逐时天文潮预测（2017/2018/2023，52,560 样本）
- 方法：8 主分潮（M2/S2/N2/K2/K1/O1/P1/Q1）最小二乘拟合
- 精度：全量 RMSE 0.108m（长洲）/ 0.115m（鰂魚涌）；时间外验证（2017-18 拟合 → 2023 预测）RMSE 0.130m
- 输出：任意日期逐时天文潮（缓存谐波系数 pkl）

### ② 台风增水参数化
```
surge = (1013 − p_hPa) × 1cm        ← 气压反效应（低压吸升）
      + V²/(22.5·R) · exp(−d/R)     ← 风堆积（切向风输送，R=50km 最大风速半径）
```
量级校验（与文献一致）：山竹 0.63m / 天鸽 0.74m / 苏拉 1.13m（掠过珠江口 0.5-1.5m 范围内）

### ③ 预警水位分级（参照《深圳市沿海风暴潮预警地方标准》量级）
| 等级 | 阈值（CD 基准） | 含义 |
|------|----------------|------|
| 关注 | ≥ 2.6 m | 沿海低洼区需留意 |
| 警戒 | ≥ 3.0 m | 达警戒水位 |
| 严重 | ≥ 3.5 m | 严重风暴潮 |

### ④ API
| 接口 | 说明 |
|------|------|
| `GET /api/surge/live?hours=48` | 实时：两站潮位曲线 + 增水 + 预警分级 |
| `GET /api/surge/tide/{station_id}` | 单站天文潮推算 |
| `POST /api/surge/estimate` | 增水参数化计算（wind/dist/pres → m） |
| `GET /api/surge/archive` | 历史事件档案（含增水复算） |

### ⑤ 集成
- **指挥中心**：四灾种卡「风暴潮」显示峰值水位 + 等级 + 增水估计（原为占位"—"）
- **态势总览**：新增「🌊 风暴潮 · 潮位推算与增水叠加」面板——双站切换、天文潮/总水位双曲线、预警阈值虚线（关注/警戒/严重）
- **城安助手**：实时快照注入风暴潮段；新增潮位/潮汐/风暴潮/涨潮等触发词；预置问题「现在潮位多高？有风暴潮风险吗？」
- **知识库**：山竹案例补增水复算字段（+0.63m = 气压 0.53 + 风堆积 0.10）

### 诚实边界
- 增水为参数化量级估计（非 ADCIRC/SWAN 类数值模式），未包含深圳湾/大鹏湾地形共振放大
- 无实测潮位接入（HKO 实测接口反爬限制）；天文潮推算精度 ±13cm
- 预警水位不替代官方发布（页面已标注）

### 模型升级 v2.1（检验中发现并修复）

检验 ④ 发现 AUC 漂移（展示 0.8066 vs 训练 0.8131）→ 根因是 v2 训练脚本
声称选 v2-single 却保存了 ensemble。修复：

- 嵌套时间切分选型（2013-20 训练 → 21-22 验证）做公正模型选择
- 最终 v2.1：21 维特征 + depth=4 / l2=2.0 正则化

- pickle 改用标准 sklearn 类（消除自定义类反序列化问题）
- 诚实记录：v2 特征工程提升在年度噪声边缘；样本实为 293 个独立预警日
