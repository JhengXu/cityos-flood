# 数据契约 v2 · 独立事件水深、可用时间与无泄漏回放

> 版本：v2（独立观测契约）
> 用途：定义真实历史内涝事件如何被守恒状态模型校准、残差学习和独立回放消费。
> 硬约束：规则/物理教师生成的标签、由“受影响区”扩展出的逐时标签和事后不可用数据，均不得进入技巧验证。
> 架构说明：[`model_v3_architecture.md`](model_v3_architecture.md)。

---

## 0. 一句话

本契约把深圳历年**真实内涝事件**的「**当时可用的降雨/预报 + 独立观测水深 + 控制状态 + 灾情记录**」规范为事件级数据集。它同时保存物理时间和系统可用时间，以支持真正的 forecast-as-issued 回放。

---

## 1. 事件目录不是监督标签

台风山竹（2018-09-16）、深圳“9·7”极端特大暴雨（2023-09-07）等公开报道事件只能作为回补数据的检索入口。报道中的“受影响区”、全市峰值雨强或文字灾情不能扩展成逐区逐时水深，也不能直接进入训练/测试表。

一个事件只有在取得可追溯的自动站/雷达雨量、当时签发的预报版本、独立水深/积水点记录及其到达时间后，才可登记为 `event_id` 并进入下述数据容器。行政区影响范围、峰值和阈值标签必须从这些权威原始记录按冻结规则计算；未知字段保持缺失，不用代表值补齐。

## 3. 表结构与字段契约

### 3.1 逐时降雨 `rainfall_stations.csv`（感知输入）
| 字段 | 类型 | 说明 |
|---|---|---|
| `event_id` | str | 独立暴雨/台风事件标识；用于分组切分 |
| `valid_at` | ISO8601 | 雨量有效时间（必须含时区） |
| `available_at` | ISO8601 | 该值实际进入系统、可供预测使用的时间 |
| `forecast_issued_at` | ISO8601/null | 预报签发时间；地面实况为空 |
| `model_run_id` / `member_id` | str/null | 原始气象预报版本和集合成员 |
| `station_id` | str | 站点/采样点（对应 30 街道点） |
| `district_id` | str | 所属行政区（如 `baoan`） |
| `rainfall_mm` | float | 该小时降雨量(毫米/小时) |

### 3.2 分区积水 `waterlogging.csv`（监督标签 · 核心）
| 字段 | 类型 | 说明 |
|---|---|---|
| `event_id` | str | 独立事件标识 |
| `observed_at` | ISO8601 | 水深观测对应的物理时间 |
| `available_at` | ISO8601 | 观测真正可用于在线预测/同化的时间 |
| `district_id` | str | 行政区 |
| `station_id` | str | 原始站点/积水点标识；区级聚合须保留成员关系 |
| `water_depth_m` | float | 质控后的独立观测积水深度（米），无积水=0 |
| `flooded` | 0/1，可选 | 兼容标签；必须记录其业务阈值/定义，不能替代连续水深 |
| `quality_flag` | str | 原始/自动/人工质控结果 |
| `vertical_datum` | str/null | 水位或高程基准；未知时不得跨站比较绝对高程 |

> 连续 `water_depth_m` 是核心目标；阈值事件从独立水深按冻结规则派生。只有 `flooded` 的文件可兼容落盘，但不能用于连续深度模型训练/校准。

### 3.3 灾情记录 `disaster.csv`（佐证/校验）
| 字段 | 类型 | 说明 |
|---|---|---|
| `timestamp` | ISO8601 | 小时 |
| `district_id` | str | 行政区 |
| `kind` | str | 灾情类型（道路封闭/交通中断/停课停工/地铁倒灌…） |
| `severity` | 0-4 | 严重程度 |
| `note` | str | 描述 |

### 3.4 事件元数据 `meta.json`
```jsonc
{
  "id": "2018-09-16_mangkhut",
  "name": "台风山竹",
  "date": "2018-09-16",
  "affected_districts": ["yantian","dapeng","baoan","nanshan","longhua"],
  "peak_intensity_mm_h": 70,
  "source": "深圳市气象局/深圳特区报",
  "version": "v0.1"
}
```

## 4. 模型输入与可见性

任一起报时刻 `T0` 只能使用 `available_at <= T0` 的记录。观测还需满足 `observed_at <= T0`；气象预报允许 `valid_at > T0`，但必须来自 `forecast_issued_at <= T0` 的原始签发版本。候选特征包括：
| 特征 | 来源 | 归一化 |
|---|---|---|
| 当前/预报降雨成员 | 自动站、雷达、原始 NWP run | mm/h |
| 前期累计雨量 | 起报时已经可用的历史雨量 | mm |
| 预报状态 | 状态空间模型的体积/深度集合 | m³ / m |
| 静态空间属性 | DEM、下垫面、经核验的管网/泵站参数 | 原始单位 |
| 潮位/河道边界 | 统一基准面的实测或原始签发预报 | m |
| 控制状态 | 泵站、闸门、封堵/维护状态 | 原始业务量 |

> DEM/WorldCover/OSM 派生特征是可追溯的空间先验，但“排水能力”和“历史易发指数”不等同于权威水力状态或独立积水标签；应由管网台账和事件观测替换/校准。

## 5. 起报、地平线与事件切分

- **起报**：对每个事件按业务节奏生成 rolling-origin 起报点，完整冻结当时可用输入快照。
- **地平线**：至少分别报告 1/3/6/12/24h；不得只选择事后效果最好的时段。
- **切分**：按 `event_id` 分组并按时间排序；同一事件的站点、行政区和重叠时间窗绝不跨 split。
- **最终测试**：锁定若干后发生独立事件；测试标签和逐事件结果在模型/阈值冻结前不可见。
- **复现**：保存数据 manifest、处理代码版本、参数、随机种子、预报 run/member、阈值和空间映射版本。
- **样本不足**：独立事件不足以同时覆盖开发与测试时，状态必须保持 `insufficient_data`，不能按随机行切分凑指标。

## 6. 可训练/可验证资格

| 数据 | 可用于运行测试 | 可用于参数/残差学习 | 可用于技巧验证 |
|---|---|---|---|
| 独立质控水深 + 双时间字段 | 是 | 来源审核后可以 | 事件外锁定测试可以 |
| 只有 `flooded` 且定义可追溯 | 是 | 仅二分类探索 | 需独立事件与可用时间审计 |
| 物理/规则教师生成标签 | 是 | 否 | 否 |
| 新闻“某区受影响”扩展标签 | 仅事件检索 | 否 | 否 |
| 事后重分析/最新预报替代当时预报 | 是 | 只能明确作为 hindsight 实验 | 否 |

## 7. 质量校验（加载前）

- 时间戳含时区、事件/站点/时间键无重复，`available_at` 不早于物理观测时间。
- `flooded∈{0,1}`；若同时有水深，必须审计两者的阈值一致性。
- 特征量纲合法（`rainfall_mm≥0`、`water_depth_m≥0`）。
- 缺失值：按小时插值 + 掩码标记（`NaN` 作为一等公民，不静默丢弃）。
- 校验函数：`dataset.validate(split)` 返回通过/失败清单。
