> 版本：v0.1（真实数据契约）

>       并落地「固定数据切分 + 固定随机种子 + 数据集版本化」的可复现验证体系。

## 0. 一句话

本契约把深圳历年**真实内涝事件**的「**逐时降雨 + 分区积水 + 灾情记录**」规范为可直接训练的
监督数据集格式，作为「降雨 → 城市状态 → 内涝」时序模型的**真实标签来源**，替代物理教师合成标签。

## 3. 表结构与字段契约

### 3.1 逐时降雨 `rainfall_stations.csv`（感知输入）
| 字段 | 类型 | 说明 |
|---|---|---|
| `timestamp` | ISO8601 | 小时时间戳（Asia/Shanghai） |
| `station_id` | str | 站点/采样点（对应 30 街道点） |
| `district_id` | str | 所属行政区（如 `baoan`） |
| `rainfall_mm` | float | 该小时降雨量(毫米/小时) |

### 3.2 分区积水 `waterlogging.csv`（监督标签 · 核心）
| 字段 | 类型 | 说明 |
|---|---|---|
| `timestamp` | ISO8601 | 小时时间戳 |
| `district_id` | str | 行政区 |
| `depth_cm` | float | 该区该小时最大积水深度(厘米)，无积水=0 |
| `flooded` | 0/1 | 是否发生内涝（深度≥阈值，如 15cm） |
| `level` | 0-4 | 风险等级（无/低/中/高/极高） |

> `flooded` / `level` 是**监督训练标签**（"是否内涝""等级"），由真实积水记录得到。

### 3.3 灾情记录 `disaster.csv`（佐证/校验）
| 字段 | 类型 | 说明 |
|---|---|---|
| `timestamp` | ISO8601 | 小时 |
| `district_id` | str | 行政区 |
| `kind` | str | 灾情类型（道路封闭/交通中断/停课停工/地铁倒灌…） |
| `severity` | 0-4 | 严重程度 |
| `note` | str | 描述 |

### 3.4 事件元数据 `meta.json`
```jsonc
{
  "id": "2018-09-16_mangkhut",
  "name": "台风山竹",
  "date": "2018-09-16",
  "affected_districts": ["yantian","dapeng","baoan","nanshan","longhua"],
  "peak_intensity_mm_h": 70,
  "source": "深圳市气象局/深圳特区报",
  "version": "v0.1"
}
```

## 4. 模型输入特征（LSTM/Transformer）

由上述真实数据派生的**特征张量**（每区每小时一维）：
| 特征 | 来源 | 归一化 |
|---|---|---|
| `excess` | `max(0, rainfall_mm - drainage_design)` | /50 |
| `cum24` | 前 24h 累计降雨 | /150 |
| `vuln` | 城市本底脆弱性（DEM/下垫面/历史/临海） | 0-1 |
| `drainage` | 该区排水设计标准 mm/h | /40 |
| `tide` | 潮位（半日潮 + 抬升） | 0-1 |

> 城市状态属性（DEM 高程、下垫面、排水、临海度、历史易发指数）来自**真实城市特征**（Open-Elevation 真实 DEM + 真实历史事件指数 + 待接入的权威 GIS/市政台账）。

## 5. 时间步与切分（可复现 · §3.2）

- **输入窗口** `SEQ_LEN=24h`；**预测地平线** `HORIZON=24h`。
- **切分**：按事件/时间切分，**固定切分比例** `train 0.6 / val 0.2 / test 0.2`。
- **随机种子**：`SEED=42`（torch/numpy 全局固定）。
- **版本化**：数据目录带 `version`（如 `v0.1`）；训练产物落 `run_dir` 含 config 副本 + 权重 + scaler。
- **防泄漏**：同一事件不跨训练/测试集；测试集仅由独立、后发生事件构成（或按时间窗留出）。

## 6. 真实数据 vs 演示数据（诚实标注）

| 模式 | 触发条件 | 说明 |
|---|---|---|
| **真实模式** | `backend/data/events/` 存在真实 `waterlogging.csv` | 直接用真实积水做监督标签 |
| **演示模式** | 真实水积水台账未注入 | 按本契约格式生成**遵循契约的演示序列**，标签锚定真实事件事实（真实日期/真实影响区/真实峰值），并在 UI 明确标记「演示样例」 |

> 目标：真实数据一旦注入，系统**零改动**切换到真实监督训练（契约不变，仅数据源变化）。

---

## 7. 质量校验（加载前）

- 时间戳单调、无重复小时。
- `flooded∈{0,1}`、`level∈{0..4}`。
- 特征量纲合法（`rainfall_mm≥0`、`depth_cm≥0`）。
- 缺失值：按小时插值 + 掩码标记（`NaN` 作为一等公民，不静默丢弃）。
- 校验函数：`dataset.validate(split)` 返回通过/失败清单。

---

## 8. 接入点（代码）

- 数据加载：`backend/app/events.load_real_data()` 读取 `events/*/`。
- 训练入口：`ml/dataset.load()` 优先读真实数据，缺失则按契约生成演示序列。
- 标签：真实 `flooded/level`；演示用真实事件事实。
- 评估：`ml/evaluate.run()` 输出命中/漏报/误报/提前量/AUC/校准曲线。
