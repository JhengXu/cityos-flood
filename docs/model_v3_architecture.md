# CITY OS 深圳内涝模型 v3.2：守恒状态空间、集合预报与 EnSRF

> 状态：已实现的灰盒基线；尚未完成独立历史事件技巧验证。
>
> 适用范围：深圳 10 个行政区、小时尺度、城市级预警与 What-if 比较。它不是街道级二维水动力求解器，也不能替代水务/气象部门的正式预警。

## 1. 为什么不再以“物理模型生成标签 → LSTM”作为核心

旧链路把规则或物理代理的输出当成训练标签，再用 LSTM/Transformer 拟合这些标签。这样最多得到一个更难解释的代理模型，不能凭空增加真实世界信息：训练目标与教师同源，测试数据若仍由同一教师生成，AUC、Brier 和命中率只说明“学生复现教师”，不说明能预测真实积水。

v3 的原则是：

1. 在真实事件数据不足时，直接运行可审计的物理状态转移，不伪装成已训练的 AI。
2. 预测和情景推演共用同一套动力学，避免 `/predict` 与 `/simulate` 互相矛盾。
3. 主输出是有单位的积水深度和体积，不是来源不明的风险分数。
4. 不确定性通过参数集合传播；有新鲜观测时用确定性局地 EnSRF 修正状态。
5. 数据驱动模型只在获得独立事件后学习物理残差或参数，不再学习自生成标签。

## 2. 在线计算链路

```text
气象预报签发快照 ─┐
历史/可用观测雨量 ─┼─> 24h地表存水spin-up ─> 分区小时强迫 ─> 守恒图状态转移 ─> 参数集合 ─> 深度分位数/阈值超越
潮位/风暴增水 ─────┤                         │
DEM/不透水/低洼 ───┤                         ├─> 水量平衡审计
排水/泵站控制 ─────┘                         │
                                              └<─ 新鲜质控水深 ─> 局地 EnSRF

同一 forecast_run_id + seed
          ├─ PREDICT：原始强迫
          └─ SIMULATE：只改变明确的情景控制量，做成对反事实比较
```

对应模块：

- `backend/app/state_model.py`：状态、守恒通量、分区有向图、参数集合、EnSRF。
- `backend/app/observations.py`：水位质控、站点到行政区的显式映射、新鲜度门槛和数据就绪度。
- `backend/app/weather.py`：带窗口选择、冻结/可用时刻和 `forecast_run_id` 的预报快照。
- `backend/app/forecasting.py`：在线预测编排与兼容 API 序列化。
- `backend/app/simulate.py`：复用同一状态模型的情景推演。
- `backend/app/userdata.py`：手工降雨情景的同源集合推演；CSV 仅质控落盘，不自动训练。

天气快照同时保存起报前 24 个已完整结束小时的降雨。[Open-Meteo 小时变量说明](https://open-meteo.com/en/docs#hourly=precipitation)
将 `precipitation` 定义为时间戳之前一小时的累计量，因此 spin-up 只接纳时间戳不晚于快照冻结时刻、
连续且完整的 24 个小时；缺测则回退零水深并加质量标志，不插值伪造。该过程只恢复地表存水
记忆，不包含土壤含水量/下渗状态；Open-Meteo 近时段值也是模式估计，不能称为深圳站点实况。
在线抓取在供应方响应到达后才记录 `forcing_selection_as_of` 并选择未来窗口；完整处理和校验结束后
才写入 `issued_at` / `snapshot_created_at` / `available_at`。若请求跨过整点并使首个有效小时过期，
系统会重取/重选，而不会把请求开始时间倒签成冻结时间。

### 2.1 与 WAM / MDP 的关系

系统层可以写成受控、部分可观测的状态空间世界模型（也可视为 POMDP 的动力学部分）：

```text
x(t+1) = fθ(x(t), u(t), a(t), G)
y(t)   = h(x(t)) + ε
```

- `G` 是 DEM、地表覆盖、河网和排水拓扑等静态城市结构；它不仅决定初态，也持续约束状态转移；
- `x` 是积水体积/水深等不可完全观测的动态状态；
- `u` 是降雨、潮位、河道边界等外生环境强迫；
- `a` 是泵站、闸门、排水和响应调度；
- `y` 是传感器观测，EnSRF 用它修正状态；
- 优化目标采用成本而非抽象奖励：积水、暴露、道路中断、能耗和动作切换代价。

当前已实现 `fθ`、观测更新、成对反事实，以及建议模式的有限时域鲁棒 CEM 常值保持控制：
它为十区搜索一组排水控制倍率，经过设备边界、首步变化、应急预算和 16 成员无恶化护栏后
输出建议。它不是一次调用内优化多时段动作序列的严格 MPC，也不是强化学习端到端学出的策略。
只有积累足够的真实“状态—行动—结果”日志后，才评估约束 MPC 与 offline/model-based residual RL。

## 3. 状态和质量守恒

每个行政区的预报状态为地表积水体积 `S[d,t]`（m³）。每小时先基于同一时刻状态计算全部区际通量，再同步更新：

```text
S[d,t+1] = S[d,t]
           + runoff[d,t]
           + routed_in[d,t]
           - routed_out[d,t]
           - drainage[d,t]
           - external_outflow[d,t]
```

其中：

- `runoff`：降雨深度 × 行政区面积 × 产流系数；
- `drainage`：排水设计代理 × 产流系数 × 潮位可用度 × 泵效/控制；
- `routed_in/out`：按 DEM 高差、质心距离和滞蓄比例构造的下坡区际通量；
- `external_outflow`：超过浅层滞蓄阈值后，经河道/城市边界离开系统的显式通量，并受潮位回水和泵效影响；
- `depth`：由连续的两段式蓄水曲线反演。0–0.15m 使用局部洼地面积，超过 0.15m 后使用更大的扩展受淹面积，避免用单一小面积把体积夸大成数米水深。

所有区际通量从更新前状态同步计算，因此不会因行政区遍历顺序不同而改变结果。每次运行输出节点残差、系统残差和闭合误差。前 24 小时 spin-up 是物理通量闭合的滚动；随后为表达初态结构不确定性而增加的先验离差，以及 EnSRF 观测更新，都是非物理状态修正，必须与降雨、排水和区际通量分账。

## 4. 集合与输出语义

在线使用固定的 64 成员规范集合，并扰动六类参数：产流系数、有效排水能力、浅层洼地面积、扩展受淹面积、区际汇流速度和外部边界排泄率。同一个 `forecast_run_id` 的预测、原始降雨、基线推演、海洋边界/潮雨错峰实验、街道/网格/PNG、可达性、反事实与手工观测同化产品共享强迫快照；集合产品还共享参数成员、初始状态和 `model_run_id`。前端从主预测向所有衍生请求透传 `forecast_run_id` 与 `forecast_days`，避免在同一页面混入不同签发批次。固定 `seed` 时结果可复现。输出包括：

- `depth_p10/p50/p90`：参数集合的积水深度分位数；
- `threshold_prob`：集合成员超过 0.05/0.15/0.30/0.50m 的比例；
- `members`、`seed`、参数来源和水量平衡审计。

`threshold_prob` 是集合频率，不是经过独立事件校准的真实发生概率。完成事件级可靠性校准前，界面和报告必须保留这一区别。

集合目前只表达参数不确定性。下一步应接入气象集合成员，使降雨落区、峰值和时序误差也进入传播链路。

集合结果保存在最多 4 个快照的进程级 LRU 中，不嵌入 32 个强迫档案；细网格逐时时序使用
cell-major 的 `uint8` 概率和 little-endian `uint16` 毫米深度编码，网格 LRU 同时受 4 项和 24MiB
上限约束。资源上界只改变传输/缓存表示，不改变守恒状态转移或峰值摘要。

## 5. 观测同化

状态模型当前使用确定性串行局地集合平方根滤波（EnSRF）：

1. 将体积集合转换到水深空间计算协方差，避免行政区面积造成尺度偏差；
2. 仅同化已知行政区、非负、质控通过、在新鲜度窗口内且 `available_at <= forecast_issued_at` 的观测；缺少可用时间审计时 fail closed；
3. 用行政区距离进行局地化，限制单站对远处分区的虚假相关；
4. 不给观测人为加随机噪声；用平方根更新收缩集合离差，返回同化前后均值、标准差、创新量、增益和体积修正；
5. 观测过期或缺失时保持预报状态，不用默认水深“假装观测”。

当 `observations.initial_analysis.applied=true` 时，初始状态账本明确区分三个体积字段（单位均为 m³，均为集合成员总蓄水变化的集合均值）：

- `structural_prior_increment_mean_m3`：在物理 spin-up 状态周围加入结构性先验离差后，相对 spin-up 状态的蓄水变化。离差在水深空间构造，并受非负约束和非线性深度—体积曲线影响，故其体积均值不保证为零；这是模型结构不确定性，不是物理入流。成员范围另由 `structural_prior_increment_p10_m3` / `structural_prior_increment_p90_m3` 给出。
- `assimilation_increment_mean_m3`：EnSRF 后验状态相对上述“已加入结构离差的先验状态”的蓄水变化；它只表示观测信息修正，不是降雨或其他物理通量。
- `total_nonphysical_initial_state_increment_mean_m3`：逐成员先相加“结构先验增量 + EnSRF 增量”，再取集合均值的初态非物理总修正。它是端到端水量账本应使用的总量；由于显示字段分别舍入，不应由两个已舍入均值重新相加替代。

物理预报期的守恒审计从同化后的分析初态开始；若要从 spin-up 末态做端到端核算，必须显式加上 `total_nonphysical_initial_state_increment_mean_m3`，不得把它塞入降雨或边界入流。

点位水位没有被硬覆盖成整个行政区水深。系统先构造分区初始集合，再以 0.10m 的代表性误差（叠加传感器误差）更新；这仍是待站点零点、观测算子和高分辨率汇水区资料替换的保守代理。

项目内水位缓存止于 2026-08-20，而当前运行日是 2026-08-24，因此它只能用于管线/QC测试和历史回放，不能作为当前实时状态同化。

## 7. 无泄漏时间契约

每条动态数据至少要保留两个时间；预报产品需要三个时间：

- `observed_at` / `valid_at`：现象发生或预报有效的物理时间；上传兼容列 `timestamp` 等价于 `observed_at`。
- `available_at`：该条记录实际进入系统、可被模型看到的时间。
- `forecast_issued_at`：模型或气象预报的签发/起报时间；原始 NWP 还要保存 `model_run_id`。

对起报时刻 `T0` 的回放只能读取 `available_at <= T0` 的数据。观测特征还应满足 `observed_at <= T0`；气象预报可以有 `valid_at > T0`，但必须来自 `forecast_issued_at <= T0` 的真实历史预报版本。不能用事后实况、最新重分析或后来修订的预报替代当时可用信息。

`T0` 必须来自冻结快照自身带时区的 `issued_at`，即完整强迫响应处理、校验并实际可用的冻结时刻，不是网络请求开始时刻，也不是供应方模式周期。快照缺少该字段时，系统把初始分析标为 `applied: false` 并拒绝读取观测；不得用请求发生时的服务器 wall clock 代替，以免同一 `forecast_run_id` 在不同时间得到不同初态。实时同化接口与页面同样透传并回传主预测的 `forecast_run_id` / `forecast_days`。

数据切分以 `event_id` 为基本组，同一台风/暴雨过程的任何站点和时间窗都不得跨训练、验证、测试集。推荐按时间顺序做 rolling-origin 回放，并把最终若干独立事件完全锁定为测试集。

## 8. 何时以及如何加入机器学习

数据驱动部分按证据量逐级增加：

1. **现在**：守恒状态空间确定性版、参数集合版、集合 + EnSRF；与零积水、持续性和简单消退基线比较数值行为。
2. **少量独立事件**：用层级贝叶斯或带约束优化校准产流、排水、蓄水面积与路由参数；报告后验范围。
3. **数十个独立湿事件**：优先训练梯度提升树/广义加性模型学习物理残差 `observed_depth - physical_depth`，保留非负和干态护栏。
4. **覆盖多季、多区、多个强度分层后**：比较 TCN/TFT、图神经状态空间或神经算子，但主状态仍应有单位并接受守恒约束；模型选择只看事件外推测试。
5. **取得管网与二维水动力结果后**：SWMM/二维浅水模型用于离线校准和高保真场景库；快速代理只能在其适用域内替代昂贵求解。

## 9. 独立验证协议

所有候选模型在完全相同的起报时刻、输入可用性和事件划分上比较：

- 连续深度：MAE/RMSE、分位数损失、CRPS、峰值深度误差、峰值时刻误差、消退时间误差；
- 阈值事件：15/30/50cm 的命中、漏报、误报、F1/CSI、Brier 与可靠性；
- 时效：逐提前量 1/3/6/12/24h 分层；
- 空间与强度：按行政区、暴雨等级、沿海/内陆、潮位状态分层；
- 不确定性：bootstrap 事件级置信区间；
- 物理审计：质量闭合、非负、排水/泵效单调性和状态更新顺序不变性。

在协议跑完前，数值模型“更高级”指结构和审计能力更完整，不代表已经证明“更准确”。

## 10. 已知限制与替换顺序

1. 分区尺度无法解析道路、下穿隧道和管网节点，应尽快升级为子汇水区/管网图。
2. 行政区面积、有效洼地面积、产流与排水参数仍需权威台账和事件校准。
3. 当前区际路由由 DEM 均值与质心距离构造，不能代替河网/箱涵/管网拓扑。
4. 潮位为调和潮与参数化增水代理，尚无统一基准面的深圳实测潮位校准。
5. 当前天气输入是确定性降雨序列；必须保存预报签发快照并接入气象集合。
6. 当前行政区 GeoJSON 保存的是 OSM relation 的边界线段。运行时先把线段拼成闭环；148 站中，102 站按水务站码中的区段映射，45 站通过修复后的区界包含判定，余下 1 站按最近真实标注易涝点回退。站码与坐标区界冲突会写入 `coordinate_check`，仍应以权威闭合边界和人工核验站点台账最终复核。
